# T2S 离线评测

从 Python 项目根目录运行，使用已启动的 T2S 服务和同一份课程 MySQL 数据：

```powershell
$env:PYTHONPATH = (Join-Path $PWD 'src')
.\.venv\Scripts\python.exe -m evals.run
```

可用 `--case Q05` 单独复跑，或用 `--output .run/evals/after-change` 保留对照报告。默认输出每题明细 JSON 与 Markdown 报告到 `.run/evals/latest/`。退出码 0 表示全部通过，1 表示有评测失败或违规，2 表示运行错误、环境不可用或安全检查缺少可用轨迹。

- `cases.json` 固定 12 道题与每轮预期；日期使用含起不含止区间。多轮补充用自然语言 `reply`，与网页的文字修改走同一条入口。
- 标准题 A01–A03 来自第 16 课的独立标准 SQL。额外参考 R01–R02 放在 `references.sql`，只用课程数据和读取账号计算。
- 查询题要通过每轮阶段、计划、执行结果和轨迹检查。结果同时比对行数、分组和值。计划不符时终止该题，避免脚本批准错误的查询。字段指标提供已检查分母，同时报告有多少预期确认卡可供比对。
- 追问题按缺字段集合评分，补齐后继续校验计划与结果。超范围题要求拒绝。取消单独用一条固定计划做安全对照，该对照不计入 12 道模型题。
- 客户端错误、服务进入 error、参考查询失败或轨迹无法验证会单独记录。规划器的公开错误信息同时覆盖模型不可用和输出无法解析，两者无法仅凭响应细分，可用会话 ID 对照服务日志。
- 没到合法确认时不应产生 SQL 开始事件。完成后重提同一版本，应收到 409，且整段会话只有一次 SQL 开始。缺失或裁剪的轨迹记为无法验证。

规则与模型的配对实验见 [对照评测](comparison/README.md)。实验题集独立于本文的 12 道回归题。
